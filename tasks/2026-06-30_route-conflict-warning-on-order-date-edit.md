# Попередження про конфлікт маршруту при зміні дати замовлення

## Статус
done

## Задача
Коли менеджер редагує дату замовлення, а доставка вже розподілена в маршрут — попередити про конфлікт і дати змогу безпечно видалити доставку з маршруту.

## План
- [x] Додати `remove_delivery_from_route()` в `route_service.py`
- [x] Модифікувати `order_edit` в `orders/routes.py` — повертати `route_conflict` без збереження
- [x] Додати модальне вікно в `list.html`
- [x] Додати JS обробку `route_conflict` і force-підтвердження в `_composer_script.html`

## Реалізація

### `app/services/route_service.py`
Нова публічна функція `remove_delivery_from_route(delivery)`:
- Знаходить `RouteDelivery` для доставки
- Видаляє зупинку, скидає `delivery.status = 'Очікує'`, `delivery.courier_id = None`
- Якщо маршрут порожній → видаляє маршрут
- Якщо маршрут `sent`/`accepted` і є зупинки → встановлює `content_changed_at`
- Повертає `{route_id, route_status, remaining_stops, route_deleted}`

### `app/blueprints/orders/routes.py`
`order_edit` POST-гілка:
- Парсить `new_date` до виклику `update_order`
- Якщо дата змінюється і `force_date_change != 'true'` і доставка `'Розподілено'` → повертає `{'route_conflict': {...}}` (200, без збереження)
- Якщо `force_date_change=true` → зберігає + видаляє з маршруту через `remove_delivery_from_route`

### `app/templates/orders/list.html`
Модальне вікно `#routeConflictModal`:
- Показує деталі маршруту (ID, дата, кур'єр, статус, кількість зупинок)
- Попередження якщо маршрут `sent`/`accepted`
- Кнопки: "Видалити з маршруту і зберегти" / "Скасувати"

### `app/templates/orders/_composer_script.html`
- Обробка `data.route_conflict` → виклик `showRouteConflictModal()`
- Функція `showRouteConflictModal(conflict, fd, url)` — показує модаль і при підтвердженні повторно відправляє запит з `force_date_change=true`
- Після успішного force-запиту — тост з номером маршруту (якщо не видалено)

## Як тестувати
1. Знайти доставку зі статусом `Розподілено` (вона в якомусь маршруті)
2. Відкрити замовлення, змінити дату → зберегти
3. Має з'явитись модальне вікно з інфо про маршрут
4. Натиснути "Скасувати" → дата НЕ змінилась, маршрут не зачеплено
5. Знову змінити дату → "Видалити з маршруту і зберегти"
6. Дата збережена, доставка вийшла з маршруту, статус скинуто в `Очікує`
7. Якщо маршрут мав інші доставки — він залишився, але `content_changed_at` встановлено якщо був `sent`
8. Якщо доставка була єдиною в маршруті — маршрут видалено

## Edge cases
- Доставка вже не в маршруті на момент force-запиту → `remove_delivery_from_route` нічого не робить (повертає `{}`)
- Маршрут у статусі `draft` → просто видаляємо зупинку, без позначки `content_changed_at`
- Доставка `'Очікує'` або `'Доставлено'` → перевірка не спрацьовує, збереження йде звично
