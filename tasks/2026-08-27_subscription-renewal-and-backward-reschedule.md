# Продовження підписки: вибір дати + каскад перенесення назад

## Статус
done

## Задача
Дві пов'язані проблеми в логіці підписок:

1. **Продовження активної підписки** (кнопка «Продовжити підписку» в модалці
   деталей) створювало новий цикл автоматично «через тиждень після останньої
   доставки старої підписки». Треба дати менеджеру обрати дату першої доставки,
   а решту 3 доставки розставляти автоматично за поточною логікою.

2. **Каскадне перенесення наступних доставок** при зміні дати однієї доставки
   підписки працювало лише коли доставку переносили *вперед*. При перенесенні
   *назад* (напр. на тиждень раніше) підказка не з'являлась і наступні доставки
   не зсувались.

## Реалізація

### Issue 1 — вибір дати першої доставки
- `app/blueprints/subscriptions/routes.py` — `subscription_extend`: читає
  опційний `first_delivery_date` (`YYYY-MM-DD`) з форми, валідує формат і що
  дата не в минулому, передає у `extend_subscription(subscription, overrides=...)`.
  Порожнє значення → стара поведінка.
- `extend_subscription` не змінювався — гілка `overrides['first_delivery_date']`
  вже існувала.
- `app/templates/subscriptions/list.html`:
  - нова панель `#subscription-extend-panel` з `<input type="date">` +
    «Продовжити» / «Скасувати» замість `confirm()`;
  - хелпери `defaultExtendDate()` / `toISODate()` — підставляють найближчий від
    сьогодні день тижня доставки підписки (`data.delivery.delivery_day`);
  - `min` інпута = сьогодні; порожнє поле не відправляється;
  - сабміт шле `FormData` з `first_delivery_date`.
- `npm run build` — нові Tailwind-класи.

### Issue 2 — каскад назад
- `app/services/subscription_service.py` — `calculate_reschedule_plan`:
  замість одностороннього gate `if gap_days > threshold: return None`
  тепер `if abs(gap_days - interval) <= 2: return None`. Тобто підказка
  з'являється, коли ритм до наступної незавершеної доставки збито в будь-який
  бік (вперед — розрив зменшується/перекриття; назад — розрив відкривається).
  Прибрано невживану змінну `threshold`.
- У plan-dict додано `interval_days` та `gap_opened` (bool).
- `app/templates/orders/list.html` — `showRescheduleModal`: третій варіант
  плашки для `gap_opened` («Наступна доставка за N дн. — графік зсунеться раніше»).
- `apply_reschedule_plan` не змінювався — вже коректно перебудовує наступні
  доставки в обидва боки.

## Як тестувати

### Issue 1
1. Відкрити активну (не зупинену, не чернетку) підписку → «Продовжити підписку».
2. З'являється панель із датою = найближчий день доставки підписки.
3. Змінити дату на потрібний тиждень → «Продовжити».
4. Створюється нова підписка: 1-а доставка рівно на обрану дату, наступні 3 —
   з кроком підписки; стара позначається `is_extended`, знижка ескалюється.
5. Спроба обрати минулу дату → помилка, підписка не створюється.

### Issue 2
1. Тижнева підписка, доставки ПН W1..W4, усі в очікуванні.
2. Перенести доставку #2 на тиждень раніше → з'являється підказка з новими
   датами для #3, #4 (раніше на тиждень). Підтвердити → дати оновлюються,
   для статусу «Розподілено» знімається маршрут і статус → «Очікує».
3. Перенос #2 вперед — працює як раніше (регрес).
4. Зсув на ≤2 дні — підказки немає.
5. Bi-weekly аналогічно.

## Edge cases
- Остання доставка (немає наступних незавершених) → підказки немає.
- Нерегулярний графік із legit великим розривом: перенос може запропонувати
  каскад там, де раніше не пропонував — менеджер підтверджує/скасовує в модалці.
- Monthly підписки — каскад не застосовується (без змін).
- Продовження зупиненої підписки — заборонено (без змін).
