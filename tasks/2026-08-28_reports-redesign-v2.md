# Редизайн розділу «Звіти та Аналітика» (reports v2)

## Статус
in_progress

## Задача
Повна перекомпоновка `/reports`: 6 вкладок → 4, hero-грід над вкладками,
експорт у шапку, нові типи графіків, чисті таблиці, палітра `.reports-v2`
(scoped, лише для звітів). Один PR, гілка `feat/wedding-subscription-flag-2`.

## Рішення (затверджено)
- Палітра teal/slate-blue (`--r-bg:#f7f9fc`, `--r-ink:#0f172a`) — тільки під `.reports-v2`, решта CRM без змін.
- Hero-грід (4 картки) — завжди видимий над вкладками.
- Cash Flow вливається у вкладку «Огляд / P&L». Вкладка «Експорт» видаляється (→ dropdown у шапці).
- «Баланс клієнтів» — весь функціонал зберігається (редагування, коригування, пошук, фільтри, місячні смуги).
- `revenue_growth_pct` = поточний обраний період vs попередній такий самий за довжиною. «Весь час» → `None` (показувати N/A / ховати дельту).

## Каркас
- Шапка: заголовок + контрол періоду + `📥 Експорт ▾` (Замовлення CSV/Excel, Транзакції CSV/Excel, з поточним діапазоном).
- Hero-грід: Загальний дохід (+Δ%), Чистий прибуток (+маржа%), Виконано доставок (+в процесі), Активні підписки (+нових за період).
- Вкладки: [Огляд / P&L] · [Доставки та Продажі] · [LTV та Клієнти] · [Баланс клієнтів]

### Вкладка 1 — Огляд / P&L
- Вторинні P&L KPI з приховуванням нульових (Вартість квітів, Квіти % від доходу, Витрати на ЗП тощо).
- Розгортувані панелі Revenue / Витрати (наявні).
- Об'єднаний Area-графік «Динаміка» з тоглами Підписки / Разові замовлення.
- Блок Cash Flow: KPI (Надходження, Порівняння, Динаміка, Рекордний день) + місячний графік.

### Вкладка 2 — Доставки та Продажі
- KPI доставок (всього / виконано / в процесі / успішність / нові клієнти).
- Динаміка доставок (area, план vs факт).
- Розподіл по містах — горизонтальні бари, < ~2.5% → «Інші міста».
- Джерела («Звідки дізнались») — горизонтальні бари, дрібні → «Інші».
- «Хто кому купує» — donut 4 сектори (Хлопець дівчині, Дівчина іншій дівчині, Весільна підписка, Інше) + легенда праворуч (% + числа).
- Типи підписок / розміри — горизонтальні бари.
- Продажі флориста — віджет з прогрес-барами (обсяг + бонус).

### Вкладка 3 — LTV та Клієнти
- KPI весільних (`get_wedding_analytics`) + KPI LTV (`get_ltv_data`).
- Таблиця «час з нами» за періодичністю.
- Топ-10 за доставками / Топ-10 за доходом — віджети з прогрес-барами (ширина = value/max).
- Renewal rate підписок (`get_subscription_renewal_rate`).

### Вкладка 4 — Баланс клієнтів
- Той самий функціонал. Новий вигляд: чисті рядки з роздільниками, кольорові pills на «Кін.» (зелений + / червоний −), закріплений 1-й стовпчик, щільніші відступи.

## Бекенд (`reports_service.py`)
1. `get_deliveries_analytics` — групування міст < ~2.5% частки у «Інші міста» (label + сумарне значення в кінець списку).
2. `get_orders_data` — те саме для `marketing_chart`; `for_whom_chart` → топ-3 + «Інше».
3. `get_pl_data` — нове поле `revenue_growth_pct` (поточний період vs попередній рівний за довжиною; `None` якщо немає діапазону).
4. Нова `get_dashboard_kpis(date_from, date_to)` → namespace `kpis`: `revenue`, `revenue_growth_pct`, `profit`, `margin`, `deliveries_done`, `deliveries_in_progress`, `active_subscriptions`, `new_subscriptions`.
   - Реюз наявних агрегацій, без N+1.

## Фронтенд

## Як тестувати
1. `/reports` — hero-грід над вкладками, 4 вкладки, кнопка експорту в шапці.
2. Перемкнути період на місяць → hero-дельта рахується vs попередній місяць; «Весь час» → дельта прихована.
3. Кожна вкладка: графіки рендеряться, горизонтальні бари, donut з легендою праворуч, «Інші міста»/«Інші» присутні.
4. «Баланс клієнтів»: редагування → збереження коригувань, пошук, фільтри працюють; pills зелені/червоні.
5. Порожні P&L KPI (нулі) не показуються.
6. Експорт CSV/Excel з шапки завантажує з поточним діапазоном.
7. Порівняти цифри з поточною версією (`?tab=` legacy) — не мають розійтися.

## Edge cases
- «Весь час»: `revenue_growth_pct = None`, hero-дельти показують «—».
- Місяць без попереднього періоду в даних → дельта 0 / «—», не ділити на нуль.
- Місто/джерело з єдиним значенням → без бакета «Інші».
- Порожні набори даних → графіки показують заглушку «Немає даних».
- `for_whom` варіанти «не вказано» — через наявний `_label_key` / `_display_label`.
