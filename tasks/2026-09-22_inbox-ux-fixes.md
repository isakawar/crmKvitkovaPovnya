# Виправлення UX сторінки /inbox (чат-інбокс)

## Статус
in_progress — потребує `flask db upgrade` перед використанням reply-функції

## Задача
Список правок від власника продукту для сторінки `/inbox`:
1. Не видно лічильника непрочитаних у згорнутому сайдбарі
2. Не відображається іконка каналу (Telegram/Viber) в списку діалогів
3. Немає реплаю/форварду повідомлень
4. Немає кнопки ручного оновлення повідомлень
5. "Картка клієнта" відкриває сирий JSON замість модалки
6. Клік по доставці в панелі клієнта не відкриває редагування
7. Клік по підписці в панелі клієнта не відкриває редагування
8. Пошук клієнта для прив'язки показує лише телефон, а не міні-картку
9. Непрочитані повідомлення візуально погано виділені

## Реалізація

### Бекенд
- `migrations/versions/add_message_reply_to.py` — нова колонка `messaging_message.reply_to_message_id` (nullable FK на себе). down_revision = `add_message_reactions` (актуальний head на момент створення).
- `app/models/message.py` — колонка `reply_to_message_id` + relationship `reply_to`.
- `app/services/messaging/adapter.py` — `ChannelAdapter.send_text/send_media` отримали опційний `reply_to_external_id`; ігнорується адаптерами, які це не підтримують.
- `app/services/messaging/telegram_business.py` — `reply_parameters` (Bot API) в `sendMessage`/`sendPhoto`.
- `app/services/messaging/telegram_personal.py` — `reply_to` (Telethon) в `send_message`/`send_file`.
- `app/services/messaging/instagram_dm.py`, `viber.py`, `whatsapp.py` — сигнатури оновлено для узгодженості інтерфейсу, параметр не використовується (їх send API не підтримує quote).
- `app/services/messaging/inbox_service.py`:
  - `send_reply()` приймає `reply_to_id`, резолвить `external_message_id` цільового повідомлення (тільки якщо воно з тієї ж розмови), передає в адаптер, зберігає `reply_to_message_id`.
  - `serialize_message()` повертає `reply_to: {id, text}` для рендеру цитати.
  - `get_client_panel()`: додано `order_id`/`subscription_id` в кожну доставку, `id` в підписку — потрібно для модалок редагування.
- `app/blueprints/inbox/routes.py`:
  - `index()` тепер передає `delivery_types`/`sizes`/`for_whom`/`marketing_sources` — потрібні спільній модалці композера замовлень і модалці клієнта (той самий патерн, що й `integrations/leads_list.html`).
  - `reply()` приймає `reply_to` (form field).

### Фронтенд
- `app/templates/layout.html` — окремий `.sidebar-icon-badge` (крапка на іконці) для згорнутого сайдбару, прихований при `:hover` (тоді видно повний бейдж біля тексту).
- `app/templates/inbox/index.html`:
  - CSS: кольори `.conv__ch` для всіх каналів, сильніше виділення `.conv.unread`, стилі `.msg__quote`/`.ib-reply-preview`, кнопка оновлення, іконки в результатах пошуку клієнта.
  - Підключено `orders/_composer_modal.html` + `clients/modal.html` (тільки коли `channels` не порожній).
  - Підключено скрипти: `city_autocomplete.js`, `address_autocomplete.js`, `orders/_composer_script.html`, `clients.js` (в такому ж порядку, як на `integrations/leads_list.html`).
- `app/static/js/clients.js` — `loadClientData` тепер експортована як `window.loadClientData`, щоб її можна було викликати з `/inbox`.
- `app/static/js/inbox.js`:
  - `chCornerHtml()` — правильна іконка для viber ("V") замість дефолтного telegram-гліфа.
  - `window.softReload` **перевизначено** локально: спільний композер замовлень після успішного збереження робить повний `location.reload()` — на `/inbox` це скидало б відкриту розмову. Замість цього — оновлення списку/треду на місці.
  - `openSubscriptionEditorById()`/`openDeliveryEditor()` — відкривають спільну модалку композера (`window.orderComposerApi`) для доставки/підписки без переходу зі сторінки.
  - Клік на "Картка клієнта" → `window.loadClientData(id)`.
  - Reply: іконка на повідомленні (тільки для `telegram`/`telegram_personal`), прев'ю цитати над полем вводу, скасування, відправка з `reply_to`.
  - `runClientSearch()` — міні-картка з іконками замість одного рядка "телефон · інста · тг".

### Свідомо звужений скоуп (узгоджено з власником продукту)
- Форвард повідомлень — не реалізовано (жоден канал крім Telegram не дає нативно форвардити через API; сенсу мало).
- Reply працює тільки для Telegram (business + personal) — Instagram/Viber/WhatsApp API не підтримують quote довільного повідомлення.
- Клік по підписці/доставці відкриває **форму редагування** (той самий композер, що й `/orders`), а не багату детальну модалку `/subscriptions` (stop/resume/extend/видалити) — та модалка вбудована прямо в `subscriptions/list.html`, не є перевикористовуваним партіалом, і виносити її окремо означало б рефакторити живу сторінку `/subscriptions` поза скоупом цієї задачі.

## Як тестувати
Локальний docker-стек (`docker compose ps` на цій машині) вже запущений з БД `kvitkova_crm` — **схоже на реальні дані**, а `telegram-personal-bot` — це живий особистий акаунт. Тому:
- **НЕ тестувати відправку reply на реальному діалозі** — піде справжнє повідомлення реальній людині.
- **НЕ зберігати зміни** в модалці редагування замовлення/підписки/клієнта на реальних записах, поки не буде тестового клієнта.

Я перевірив без побічних ефектів (через Flask test client, без виводу реальних даних):
- `GET /inbox` → 200, весь новий HTML присутній (`sidebar-icon-badge`, `ib-reply-preview`, `ib-refresh`, `clientModal`, `addOrderModal`).
- `python -m py_compile` на всіх змінених `.py` файлах — ОК.
- `node -c` на `inbox.js`/`clients.js` — ОК.
- Jinja `get_template()` на `inbox/index.html`/`layout.html` — синтаксично ОК.
- **Виявлено і зафіксовано**: `GET /inbox/conversations/<id>/messages` зараз падає з `UndefinedColumn: messaging_message.reply_to_message_id does not exist` — очікувано, бо міграція ще не застосована до БД. **Це ламає завантаження повідомлень на всіх каналах**, поки міграція не накотиться. Не застосовував міграцію сам — по правилу з CLAUDE.md "спочатку git commit, потім flask db upgrade".

### Ручне тестування (після `git commit` + `flask db upgrade`)
1. **Згорнутий сайдбар** — згорнути сайдбар (не наводити курсор), відкрити діалог з непрочитаними — крапка з числом має бути видна на іконці чату.
2. **Іконка каналу** — відкрити `/inbox`, переконатись що кожен діалог показує кольорову іконку каналу (не білу/невидиму) в кутку аватарки.
3. **Reply** (тільки Telegram) — навести на повідомлення в telegram/telegram_personal розмові → з'явиться іконка reply → клік → над полем вводу з'явиться цитата → відправити текст → нове повідомлення в Telegram прийде як реальний reply (quote) на оригінал.
4. **Кнопка оновлення** — відкрити діалог, натиснути іконку оновлення в шапці — індикатор крутиться, список/тред оновлюються.
5. **Картка клієнта** — відкрити прив'язаний діалог → "Картка клієнта" → відкривається модалка з даними клієнта на цій же сторінці, без переходу.
6. **Доставка → редагування** — клік по картці доставки в панелі клієнта → відкривається модалка композера (звичайне замовлення або підписка, залежно від типу) з підставленими даними; після збереження — розмова лишається відкритою (без reload).
7. **Підписка → редагування** — клік по блоку підписки в панелі клієнта → та сама модалка композера в режимі підписки.
8. **Пошук клієнта для прив'язки** — відкрити неприв'язаний діалог, ввести ім'я в пошук — результати показують ім'я + рядок з іконками телефону/інстаграму/телеграму (а не один змішаний рядок).
9. **Непрочитані** — діалоги з непрочитаними мають жовтий фон + смугу зліва (не лише жирний шрифт), час підсвічено акцентним кольором, бейдж лічильника трохи більший.

## Edge cases
- Reply на повідомлення, яке ще не відправлено (optimistic bubble без `id`) — кнопка reply не рендериться, поки немає реального `id`.
- Reply на повідомлення з іншої розмови технічно неможливий через UI, але `send_reply()` додатково перевіряє `reply_to_msg.conversation_id == conversation.id` на бекенді.
- Доставка без `order_id` (не мало б траплятись) — клік нічого не робить (`openDeliveryEditor` тихо виходить).
- Підписка/замовлення видалені між відкриттям панелі клієнта і кліком — `openSubscriptionEditorById`/`openOrderEditor` покажуть toast з помилкою (обробляється існуючим кодом композера).
- Клієнт без жодного контакту (немає phone/instagram/telegram) в пошуку прив'язки — рядок міні-картки просто не рендериться (як і раніше).
