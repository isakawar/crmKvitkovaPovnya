## Задача
Список правок від власника продукту для сторінки `/inbox`:
1. Не видно лічильника непрочитаних у згорнутому сайдбарі
2. Не відображається іконка каналу (Telegram/Viber) в списку діалогів

### Follow-up: підтягування історії (item 11)
Проблема: `flask messaging-backfill-telegram-personal <id>` (весь акаунт, усі чати) відкриває
**друге** MTProto-з'єднання на тій самій сесії, що й живий воркер `telegram-personal-bot` —
це може непомітно зупинити доставку нових повідомлень, поки воркер не перезапустять
(задокументовано в пам'яті сесії, `dev_vps_access.md`). Робити з цього кнопку в UI, яку
можна натискати будь-коли, напряму — небезпечно.

Рішення: кнопка в UI просить **вже підключеного** воркера самого підтягнути історію для
однієї розмови — друге з'єднання ніколи не відкривається.
- `app/services/messaging/telegram_personal_backfill.py`:
  - `_backfill_dialog(client, dialog_entity, conv, days)` — витягнутий спільний код
    імпорту одного чату (використовує вже підключений `client`).
  - `backfill_conversation(client, conv, days)` — новий вхід для одного чату/вже
    існуючої розмови (використовується воркером).
  - `_run_async()` (весь акаунт, CLI) тепер теж використовує `_backfill_dialog()` — без
    дублювання логіки.
- `app/services/messaging/events.py` — новий канал `inbox:backfill` (окремо від `inbox:events`,
  щоб команди воркеру ніколи не потрапляли в SSE до браузера) + `publish_backfill_request()`.
  `publish()` тепер приймає `**extra` — потрібно для `imported`/`error` в подіях завершення.
- `scripts/run_telegram_personal_worker.py` — `run_channel()` тепер паралельно з
  `client.run_until_disconnected()` запускає `_listen_for_backfill(app, channel_id, client)`:
  підписка на Redis `inbox:backfill`, при команді для свого `channel_id` викликає
  `backfill_conversation()` тим самим `client`, публікує `backfill_done`/`backfill_error`
  назад через `inbox:events` (тому фронтенд бачить результат через вже наявний SSE).
- `app/blueprints/inbox/routes.py` — `POST /inbox/conversations/<id>/backfill` (`days` ∈
  {1,3,7}, інакше 7), тільки для `channel_type == 'telegram_personal'`.
- `app/templates/inbox/index.html` / `app/static/js/inbox.js` — кнопка "Оновити" для
  telegram_personal тепер відкриває маленьке меню (1/3/7 днів) замість миттєвого
  `fetchThread`; для інших каналів (webhook-only, без серверної історії) поведінка не
  змінилась. SSE-обробник показує toast на `backfill_done`/`backfill_error`.

**Важливо**: команда fire-and-forget через Redis pub/sub (без черги) — якщо воркер саме
перезапускається в момент кліку, запит просто губиться без помилки користувачу
(рідкісний випадок, прийнятно для ручної кнопки).

### Follow-up 2: створення клієнта, очищення пошуку, медіа-плеєри, швидкі відповіді (items 14-17)

**14. Створення клієнта без переходу.** `POST /clients/new` тепер повертає `client_id` в
успішній відповіді (раніше — тільки `{success: true}`, без id, тому підв'язати щойно
створеного клієнта до розмови було неможливо). `clients.js` `persistClient()` при успішному
**створенні** (не редагуванні) кидає `document.dispatchEvent('crm:client-created', {id})` —
модалка нічого не знає про /inbox, просто сповіщає. `inbox.js` слухає цю подію і при
відкритій непривʼязаній розмові одразу викликає `link-client`. Кнопка "Створити нового
клієнта" в `renderClientPanel()` просто показує вже підключений `#clientModal`
(`bootstrap.Modal.getOrCreateInstance`) — форма й так стартує в режимі створення
(`isEditMode` скидається на `hidden.bs.modal`).

**15. Очищення пошуку.** Спільний клас `.ib-clear-btn`, кнопка "✕" всередині поля
(`position:absolute`), показується через `.show` коли `input.value` не порожній. Використано
і для `#ib-search` (статична розмітка), і для `#icp-search-input` (рендериться динамічно в
`renderClientPanel()`).

**16. Медіа-плеєри.** Корінь проблеми: `_media_dicts()` в `telegram_personal.py` (Telethon)
розрізняла лише `photo`/`document` — голосові, кружечки, стікери, відео всі падали в один
кошик `document`. Тепер перевіряються `message.voice/.video_note/.sticker/.video/.gif/.audio`
і `type` виставляється відповідно. `telegram_business.py` (Bot API) вже розрізняв
voice/video — додано ще `video_note`/`sticker` (в JSON payload вони прийдуть окремими
ключами `video_note`/`sticker`). `serialize_message()` тепер віддає ще й `mime` — потрібно
фронтенду, щоб відрізнити статичний webp-стікер (рендериться як `<img>`) від
анімованого/відео-стікера (рендериться як бейдж-заглушка — Lottie/webm плеєр не
реалізовували, поза скоупом). `inbox.js` `msgNode()`: voice/audio → `<audio controls>`,
video/video_note → `<video controls>` (кружечок стилізовано круглим і меншим), photo — як і
було. Все грає прямо в сторінці через існуючий lazy-download `/inbox/media/<msg>/<idx>` —
нових ендпоінтів не знадобилось.

**17. Швидкі відповіді.** Нова таблиця `quick_reply` (`id`, `text`, `created_by`,
`created_at`) — спільні на всю команду, не приватні per-user (маленька команда, сенсу в
розділенні мало). `inbox_service.list_quick_replies/create_quick_reply/delete_quick_reply` +
3 роути (`GET/POST /inbox/quick-replies`, `POST /inbox/quick-replies/<id>/delete`). Кнопка
блискавки поруч зі скрепкою відкриває маленьке меню (список + форма додавання внизу,
той самий popover-патерн, що й для backfill). Клік по існуючій — **вставляє** текст в
textarea (не відправляє одразу) — так само, як прикріплення файлу не відправляє само собою,
дає користувачу можливість підправити перед надсиланням.

### Follow-up: ліміт розміру фото (item 10)
Причина 413 на фото >~1MB — не Flask (`MAX_CONTENT_LENGTH` = 15MB), а nginx на dev
(`/etc/nginx/sites-available/devcrm.duckdns.org`, дефолт 1MB, **не в git**). Додано
`client_max_body_size 15m;` в `location /` (бекап оригіналу зроблено на сервері перед
зміною), `nginx -t && systemctl reload nginx`. Задокументовано в пам'яті сесії — при
переналаштуванні nginx з нуля цю правку треба повторити.

### Свідомо звужений скоуп (узгоджено з власником продукту)
- Форвард повідомлень — не реалізовано (жоден канал крім Telegram не дає нативно форвардити через API; сенсу мало).
- Reply працює тільки для Telegram (business + personal) — Instagram/Viber/WhatsApp API не підтримують quote довільного повідомлення.
- Клік по підписці/доставці відкриває **форму редагування** (той самий композер, що й `/orders`), а не багату детальну модалку `/subscriptions` (stop/resume/extend/видалити) — та модалка вбудована прямо в `subscriptions/list.html`, не є перевикористовуваним партіалом, і виносити її окремо означало б рефакторити живу сторінку `/subscriptions` поза скоупом цієї задачі.

## Як тестувати
Локальний docker-стек (`docker compose ps` на цій машині) вже запущений з БД `kvitkova_crm` — **схоже на реальні дані**, а `telegram-personal-bot` — це живий особистий акаунт. Тому:
- **НЕ тестувати відправку reply на реальному діалозі** — піде справжнє повідомлення реальній людині.
- **НЕ зберігати зміни** в модалці редагування замовлення/підписки/клієнта на реальних записах, поки не буде тестового клієнта.

Я перевірив без побічних ефектів (через Flask test client, без виводу реальних даних):
- `GET /inbox` → 200, весь новий HTML присутній (`sidebar-icon-badge`, `ib-reply-preview`, `ib-refresh`, `clientModal`, `addOrderModal`).
- `python -m py_compile` на всіх змінених `.py` файлах — ОК.
- `node -c` на `inbox.js`/`clients.js` — ОК.
- Jinja `get_template()` на `inbox/index.html`/`layout.html` — синтаксично ОК.
- **Виявлено і зафіксовано**: `GET /inbox/conversations/<id>/messages` зараз падає з `UndefinedColumn: messaging_message.reply_to_message_id does not exist` — очікувано, бо міграція ще не застосована до БД. **Це ламає завантаження повідомлень на всіх каналах**, поки міграція не накотиться. Не застосовував міграцію сам — по правилу з CLAUDE.md "спочатку git commit, потім flask db upgrade".

### Ручне тестування (після `git commit` + `flask db upgrade`)
1. **Згорнутий сайдбар** — згорнути сайдбар (не наводити курсор), відкрити діалог з непрочитаними — крапка з числом має бути видна на іконці чату.
2. **Іконка каналу** — відкрити `/inbox`, переконатись що кожен діалог показує кольорову іконку каналу (не білу/невидиму) в кутку аватарки.
3. **Reply** (тільки Telegram) — навести на повідомлення в telegram/telegram_personal розмові → з'явиться іконка reply → клік → над полем вводу з'явиться цитата → відправити текст → нове повідомлення в Telegram прийде як реальний reply (quote) на оригінал.
4. **Кнопка оновлення** — відкрити діалог, натиснути іконку оновлення в шапці — індикатор крутиться, список/тред оновлюються.
5. **Картка клієнта** — відкрити прив'язаний діалог → "Картка клієнта" → відкривається модалка з даними клієнта на цій же сторінці, без переходу.
6. **Доставка → редагування** — клік по картці доставки в панелі клієнта → відкривається модалка композера (звичайне замовлення або підписка, залежно від типу) з підставленими даними; після збереження — розмова лишається відкритою (без reload).
7. **Підписка → редагування** — клік по блоку підписки в панелі клієнта → та сама модалка композера в режимі підписки.
8. **Пошук клієнта для прив'язки** — відкрити неприв'язаний діалог, ввести ім'я в пошук — результати показують ім'я + рядок з іконками телефону/інстаграму/телеграму (а не один змішаний рядок).
9. **Непрочитані** — діалоги з непрочитаними мають жовтий фон + смугу зліва (не лише жирний шрифт), час підсвічено акцентним кольором, бейдж лічильника трохи більший.
10. **Ліміт фото** — надіслати фото 3-10MB в reply — має пройти (раніше падало на nginx ще до Flask).
11. **Підтягування історії** — відкрити telegram_personal-розмову → іконка "Оновити" тепер відкриває меню з "1 день"/"3 дні"/"7 днів" → обрати → toast "Запит надіслано" одразу, за кілька секунд другий toast з результатом ("Підтягнуто повідомлень: N" або "Нових повідомлень... немає") і повідомлення з'являються в треді без перезавантаження сторінки. Для не-telegram_personal розмов кнопка лишається простим "оновити зараз" (без меню).
12. **Чипи каналів** — рядок з назвами каналів під заголовком "Чат / Інбокс" більше не показується.
13. **Backfill на "старому" контакті** — підтягнути історію в чаті з контактом, з яким давно не було активності — більше не падає з "Could not find the input entity".
14. **Створити клієнта з чату** — відкрити непривʼязаний діалог → "Створити нового клієнта" → заповнити мінімум (нік/телефон) → зберегти → модалка закривається, клієнт одразу привʼязаний до цього діалогу (без переходу на /clients).
15. **Очищення пошуку** — ввести текст в пошук діалогів або пошук клієнта для привʼязки → з'являється "✕" всередині поля → клік очищає.
16. **Медіа** — надіслати собі (або отримати) голосове, кружечок і стікер у telegram_personal-чаті → голосове й кружечок програються прямо в треді (аудіо/відео-плеєр), стікер показується як картинка без рамки бабла.
17. **Швидкі відповіді** — натиснути іконку блискавки біля скрепки → ввести текст внизу меню → "Додати" → текст з'являється в списку → клік по ньому вставляє текст в поле вводу (не відправляє одразу) → "✕" на пункті видаляє його зі списку.

## Edge cases
- Reply на повідомлення, яке ще не відправлено (optimistic bubble без `id`) — кнопка reply не рендериться, поки немає реального `id`.
- Reply на повідомлення з іншої розмови технічно неможливий через UI, але `send_reply()` додатково перевіряє `reply_to_msg.conversation_id == conversation.id` на бекенді.
- Доставка без `order_id` (не мало б траплятись) — клік нічого не робить (`openDeliveryEditor` тихо виходить).
- Підписка/замовлення видалені між відкриттям панелі клієнта і кліком — `openSubscriptionEditorById`/`openOrderEditor` покажуть toast з помилкою (обробляється існуючим кодом композера).
- Клієнт без жодного контакту (немає phone/instagram/telegram) в пошуку прив'язки — рядок міні-картки просто не рендериться (як і раніше).
- Клік "Оновити" на каналі, що не є `telegram_personal` — бекенд поверне 400, меню з днями для таких каналів і не показується.
- `telegram-personal-bot` перезапускається саме в момент кліку на 1/3/7 днів — команда в Redis pub/sub губиться без черги, користувач не отримає жодного toast; можна натиснути ще раз.
- Анімований (`.tgs`, Lottie) чи відео (`.webm`) стікер — не рендериться як картинка/відео (немає клієнтського Lottie-плеєра), показується заглушкою з іконкою й підписом "Анімований стікер", посилання на завантаження немає (можна додати за потреби).
- Швидка відповідь з порожнім текстом — кнопка "Додати" нічого не робить (`if (!text) return`), бекенд додатково відхиляє порожній текст 400-кою.
- Видалення швидкої відповіді, якої вже нема (подвійний клік) — `delete_quick_reply` повертає `False`, роут віддає `{ok: false}`, UI просто не оновлює список (без явної помилки користувачу — низький пріоритет).
