# Модалка редагування замовлення стирає тип пакування та бажаний час

## Статус
done

## Задача
Після того як менеджер проставив «тип пакування» (`bouquet_type`) або
«бажаний час» доставки, будь-яке редагування замовлення через модалку
«Редагувати замовлення» стирало ці значення.

## Root cause
Модалка редагування замовлення = той самий composer-form.

1. **`bouquet_type` / `composition_type`** — у формі **немає полів** для них.
   `update_order` все одно робив `order.bouquet_type = form.get('bouquet_type') or None`
   → `None`, а `sync_order_to_active_deliveries` затирав і `delivery.bouquet_type`.
   Тип пакування виставляється інлайн-селектом у списку замовлень
   (`/orders/<id>/bouquet_type`, пише лише `order`).

2. **`time_from` / `time_to`** — поля у формі є, але GET `/orders/<id>/edit`
   віддавав `order.time_from` **без фолбеку на доставку**. «Бажаний час»
   ставиться інлайн-віджетом (`/orders/deliveries/time`), який пише лише
   `delivery.time_from`. Тому в модалці поле порожнє → збереження затирало час.

Модалка редагування **підписки** не страждає — там усі 4 поля присутні.

## Реалізація
- `app/services/order_service.py` — `update_order` тепер оновлює
  `bouquet_type` / `composition_type` лише коли ключ реально є у формі
  (`if 'bouquet_type' in form:`). Модалка їх не шле → значення зберігаються.
- `app/blueprints/orders/routes.py` — `order_edit` GET віддає час першої
  незавершеної доставки як пріоритетне джерело
  (`first_pending.time_from or order.time_from`), бо інлайн-віджет пише саме
  в доставку.
- Без міграцій.

## Як тестувати
1. Замовлення → у списку проставити «тип пакування» (напр. Ваза).
2. Відкрити «Редагувати замовлення», щось змінити, зберегти.
3. Тип пакування лишається (список + флорист).
4. У списку проставити «бажаний час» доставки (напр. 10:00–14:00).
5. Відкрити «Редагувати замовлення» → у полях Час з/до вже стоїть 10:00 / 14:00.
6. Зберегти → час не злітає.

## Edge cases
- Час, виставлений і на `order`, і на `delivery` (напр. при створенні) —
  показується значення доставки (актуальніше).
- Доставлені / скасовані доставки не чіпаються.
- Редагування підписки — без змін (усі поля round-trip'ляться).
