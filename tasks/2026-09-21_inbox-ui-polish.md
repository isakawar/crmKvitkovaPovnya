# /inbox: Telegram/Apple-style полірування UI

## Статус
done

## Задача
`/inbox` мав відчуватись охайніше, плавніше і стабільніше — практики
Telegram Desktop і Apple (Messages/Photos): м'які easing-криви, тактильний
feedback на кнопках, згладжений скрол, групування послідовних повідомлень,
sticky дата-роздільник, fade-переходи для лайтбоксу/модалки, retry для
невдалих повідомлень.

## План
- [x] Стандартна Apple-крива `--ib-ease` на всіх transition
- [x] Fade+slide-in для нових повідомлень (не для історії/початкового завантаження)
- [x] Плавний скрол до низу для нових повідомлень, миттєвий для історії
- [x] Тактильний `:active { scale(.94-.96) }` на кнопках/табах/conv-рядках
- [x] Лайтбокс і "новий діалог" модалка — fade+scale замість миттєвого show/hide
- [x] Pending-бабл — пульсація замість статичної прозорості
- [x] Глибші тіні на бабблах, охайніші радіуси кутів
- [x] Групування послідовних повідомлень одного відправника (тісніший відступ)
- [x] Sticky дата-роздільник (з blur-фоном, спливає при скролі)
- [x] Тонкий scrollbar (list + thread)
- [x] М'якший empty-state (іконка в колі)
- [x] Unread-бейдж — pop-анімація лише при зміні значення (не на кожен полінг)
- [x] Клік на `.failed`-бабл — підставляє текст назад у composer

## Реалізація
`app/templates/inbox/index.html` (весь `<style>`-блок):
- `--ib-ease: cubic-bezier(.25,.1,.25,1)` + keyframes `ib-msg-in`/`ib-pulse`/`ib-pop`.
- `.msg { animation: ib-msg-in .2s var(--ib-ease); }`, вимикається класом `.no-anim`
  (для історії/першого завантаження треда — керується з JS, не CSS-selector'ом,
  бо CSS не знає "це нове чи старе повідомлення").
- `.msg.grouped { margin-top: -0.2rem; }` — тісніший відступ, БЕЗ приховування
  meta/timestamp попереднього повідомлення (той повний Telegram-стиль, де тільки
  останнє повідомлення групи показує час, вимагав би мутувати вже відрендерений
  сусідній вузол при кожному новому повідомленні — свідомо спрощено заради
  меншого ризику/складності).
- `.ib-date { position: sticky; top: 0.4rem; background: rgba(255,255,255,.85);
  backdrop-filter: blur(6px); }` — спливаюча дата-пігулка.
- `.ib-lightbox`/`#ib-new-modal` (той самий клас) — завжди `display:flex`,
  видимість через `opacity`+`pointer-events`+клас `.show`, з transform
  scale на внутрішньому контенті/картинці.
- Тонкий scrollbar (`scrollbar-width: thin` + `::-webkit-scrollbar`) на
  `.ib-list__scroll` і `.ib-msgs`.

`app/static/js/inbox.js`:
- `msgNode(m, opts)` — тепер приймає `{grouped, animate}`, ставить
  `data-dir`/`data-sender`/`data-ts`/`data-text` атрибути (для групування
  і retry, без окремого стану в `S`).
- `shouldGroup(m)` — звіряється з `msgsEl.lastElementChild` (єдине джерело
  правди, не паралельний JS-стан, що міг би розсинхронитись із SSE/poll-гонками).
- `appendMsgs(list, animate)` — `animate=false` для початкового завантаження
  треда (`fetchThread(true)`), `true` для живих подій (polling/SSE/власна
  відповідь на send). `scrollToBottom(smooth)` — `smooth` лише коли `animate`.
- `appendOptimistic` — той самий grouped/animate шлях, плюс тепер несе
  `sender_user_id: ME`, інакше группування власних послідовних повідомлень
  ламалось би (порожній sender_user_id в оптимістичному повідомленні не
  співпадав би з реальним id менеджера з попереднього справжнього повідомлення).
- `prependMsgs` (довантаження історії) — явний `{animate:false}`, групування
  свідомо не рахується для цього шляху (той самий trade-off, що й для meta —
  контроль ризику/обсягу).
- `setNavBadge` — pop-анімація лише коли текст бейджа реально змінився
  (`textContent !== next`), інакше кожен 10с-полінг "смикав" би бейдж
  навіть без зміни числа.
- Лайтбокс/модалка — `style.display` замінено на `classList.add/remove('show')`
  всюди (4 місця).
- `msgsEl` click-хендлер розширено: клік на `.msg.failed` підставляє
  `dataset.text` назад у `#ib-text` і фокусує поле; toast підказує
  прикріпити файл заново, якщо повідомлення було з вкладенням (файл не
  зберігається після невдалої відправки, лише текст).

## Як тестувало (локальна перевірка в браузері)
Не було ребілду Docker-образу — перевірив через `flask`-dev-server напряму
(sqlite, `threaded=True`, без Redis) + headless Chromium (Playwright,
встановлений локально в тимчасову папку, прибраний після перевірки):
1. Насіяв адміна + канал + розмову з 6 повідомленнями (текстові, включно
   з групою з 2 послідовних "out" і одним `failed`).
2. Скріншот списку розмов і треда — bubbles з тінями, sticky дата-пігулки
   з blur, групування (тісний відступ між 13:52/13:53 своїми повідомленнями)
   і failed-бабл у м'якому червоному з текстом помилки — усе відрендерилось
   як задумано.
3. Форсував `.ib-lightbox.show` вручну — fade+scale підтверджені.
4. Клікнув по `.msg.failed` — `#ib-text` дійсно заповнився текстом
   невдалого повідомлення (`"Не вдалось надіслати це повідомлення"`).
5. `console --errors` під час усього прогону — єдина помилка: `/inbox/stream`
   повернув 500, бо в локальному оточенні немає Redis (`getaddrinfo` на
   хост `redis`, який резолвиться лише всередині docker-compose мережі).
   Це **очікувано і підтверджує graceful degradation**, закладений раніше:
   сторінка і весь функціонал (список, тред, composer, лайтбокс, retry)
   продовжили працювати штатно навіть коли SSE впав.
6. Прибрав тимчасовий сервер/БД/Playwright після перевірки — нічого не
   лишилось поза `/tmp`.

`pytest tests/unit -k "messaging or inbox"` — 54 проходять (backend не
чіпався в цій задачі, суто UI-шар).

## Edge cases
- Групування рахується по `msgsEl.lastElementChild`, а не по `S`-стану —
  залишається коректним навіть коли SSE-триггерений fetch і власна
  відповідь на reply прилітають в різному порядку (той самий dedup-шлях,
  що вже існував).
- `.no-anim` явно вимикає fade-in там, де JS каже "не анімувати" — CSS сам
  не намагається вгадувати "нове це чи старе" повідомлення.
- Sticky дата-пігулка в flex-column з `overflow-y:auto` — стандартний,
  широко використовуваний патерн (той самий, що в Telegram Web/Slack),
  але не тестувався в Safari-специфічних edge-case'ах `backdrop-filter`
  (лише Chromium через Playwright) — якщо колись помітите проблему в
  Safari, перша підозра.
