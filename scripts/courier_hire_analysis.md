# courier_hire_analysis — «а що якби найняти штатного курʼєра?»

> ⚠️ **Це аналітичний інструмент, а не фіча.** Гілка `tool/courier-hire-analysis`
> існує окремо і **ніколи не мерджиться в `main`**. Оновлювати — ребейзом на
> свіжий `origin/main` за потреби.

## Що робить

Симулює день за днем, скільки історичних курʼєрських доставок за місяць зміг би
розвезти **один штатний курʼєр на зарплаті**, роблячи кілька ходок (кожна ≤ 3 год
у дорозі — свіжість квітів), і чи це дешевше за поточних сторонніх курʼєрів / таксі.

Використовує наявний сервіс оптимізації маршрутів (`ROUTE_OPTIMIZER_URL`).
**Нічого не пише в БД.** На виході — консольний звіт + самодостатній HTML.

### Алгоритм (коротко)

1. **Фаза A** — 1 виклик `/api/optimize/json` на день → K маршрутів, кожен уже
   ≤ 3 год і вкладається у вікна (оптимізатор сам це гарантує).
2. **Фаза B** — симуляція одного курʼєра: ходки послідовно, виїзд зі складу під
   вікно (`max(годинник, suggestedDepartureTime)` — до виїзду курʼєр чекає на
   складі, квіти в холодильнику), реальні ETA через `/api/recalculate`. Хто не
   встиг у вікно або в зміну → на таксі.
3. Overflow пере-декомпозується з поточного часу, поки додає прогрес
   (`_MAX_ROUNDS = 8`).

## Запуск

```bash
# весь місяць
docker compose exec web python scripts/courier_hire_analysis.py --month 2026-08

# один день (калібрування — вартість там не показова)
docker compose exec web python scripts/courier_hire_analysis.py --day 2026-08-08 --verbose

# діапазон
docker compose exec web python scripts/courier_hire_analysis.py --from 2026-08-01 --to 2026-08-07

# сітка чутливості: зміна 8/10/12 год × 1/2 курʼєри (повільно — 6 прогонів)
docker compose exec web python scripts/courier_hire_analysis.py --month 2026-08 --sensitivity
```

HTML зберігається в робочу теку контейнера (`/app`). Забрати:

```bash
docker compose cp web:/app/courier_hire_analysis_2026-08.html ./
```

## Основні параметри (усі опційні, є дефолти)

| Прапорець | Дефолт | Що це |
|---|---|---|
| `--month YYYY-MM` / `--day YYYY-MM-DD` / `--from … --to …` | — | період (один обовʼязковий) |
| `--shift-start` / `--shift-end` | `07:00` / `19:00` | зміна курʼєра |
| `--max-trip-min` | `180` | стеля «в дорозі» на одну ходку |
| `--reload-buffer-min` | `30` | перезавантаження на складі між ходками |
| `--couriers` | `1` | скільки штатних курʼєрів моделювати |
| `--salary` | `25000` | зарплата на місяць на курʼєра |
| `--car-cost` | `0` | авто + пальне на місяць (сумарно) |
| `--baseline-cost` | `270` | скільки коштує доставка зараз (сторонній) |
| `--taxi-cost` | `270` | скільки коштує overflow-доставка таксі |
| `--statuses` | `Доставлено,Розподілено,Очікує` | які статуси брати |
| `--include-cancelled` | off | додати скасовані |
| `--unroutable taxi\|exclude` | `taxi` | що робити з адресами, які не геокодуються |
| `--mode decompose\|iterative` | `decompose` | `iterative` — друга думка (K викликів/день) |
| `--sensitivity` | off | сітка зміна × курʼєри |
| `--html` / `--csv` / `--json` | авто | шляхи для дампів |
| `--optimizer-url` / `--optimizer-timeout` | з конфіга / `120` | оптимізатор |

Для діапазону/дня зарплата пропорційна кількості днів (`× дні/30.44`), щоб
порівняння було чесним.

## Модель вартості

```
N            = covered + overflow                       # маршрутизовані доставки
current      = baseline_cost × (N + unroutable_taxi)
inhouse      = (couriers×salary + car_cost) × months + taxi_cost × (overflow + unroutable_taxi)
delta        = current − inhouse                         # > 0 → наймати вигідніше
breakeven    = fixed / baseline_cost                     # скільки доставок має покрити курʼєр
```

## Що означає «Завантаження курʼєра»

`сума часу всіх ходок (виїзд зі складу → повернення) / (робочі дні × довжина зміни)`.
**Не** рахує очікування на складі, завантаження, паперову роботу. Низьке число
означає, що повна ставка завелика для поточного обсягу — а не помилку розрахунку.

## Обмеження

- Депо зашите в оптимізаторі (`вулиця Нагірна, 18, Київ`) — час у дорозі відносно нього.
- Маршрути оптимізатора «відкриті» (без плеча повернення) → кількість ходок трохи
  занижена; компенсовано синтетичною зупинкою в депо у Фазі B + `--reload-buffer-min`.
- `270 грн` — припущення: у схемі немає вартості на доставку.
- Старі адреси без координат геокодує сам оптимізатор; що не змогло → категорія «unroutable».
